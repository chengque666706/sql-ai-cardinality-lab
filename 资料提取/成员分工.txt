课题：SQL 与 AI 协同优化——基于机器学习的查询优化
一、总体研究思路
本学期小组工作继续沿用上学期“SQL 与 AI 协同优化——基于机器学习的查询优化”这一前沿调研方向，不重新开展大规模模型复现，而是在原有理论调研基础上增加一组轻量化、可复现的 PostgreSQL 实证分析。
整体研究链路确定为：
理论问题 → 数据库现象 → 实验验证 → 影响分析 → AI 方法为什么出现。
核心研究问题：
传统查询优化器的基数估计在什么情况下会出现明显失真，这种失真如何进一步影响代价估计、Join Algorithm/Join Order 以及最终执行性能，并由此说明学习型基数估计与 AI 查询优化方法的研究动机。
实验不追求论文级模型复现，重点保证问题明确、对照清楚、结果真实、结论能够与前沿调研形成闭环。

三、各成员具体工作内容
成员A：总体框架与 PPT 整合负责人
确定整份PPT的主线，不按“每个人一个独立专题”机械拼接，而是统一为“传统CBO问题—基数估计误差—执行计划影响—AI方法回应”的逻辑。
根据其他四位成员提交的结果统一制作全部PPT，负责版式、字体、图表风格、引用格式和页面节奏。
制作老师明确要求的“本学期与上学期工作的主要区别”页面，突出本学期新增的实证分析，而不是重复上学期调研。
制作总流程图、成员分工页、研究结论页，并负责最终汇报结构和各成员材料衔接。
不承担大量重复资料检索，主要职责是研究组织、成果整合和表达质量控制。
成员B：PostgreSQL 实验实施与数据采集负责人
搭建 PostgreSQL 与 TPC-H 测试环境，建议先使用 SF=1，保证普通电脑即可稳定完成实验。
选取约 10–20 条代表性查询，覆盖单表过滤、简单 Join、多表 Join 等场景。
执行 EXPLAIN (ANALYZE, FORMAT JSON)，采集各计划节点中的 Plan Rows、Actual Rows、Total Cost、Actual Total Time、Node Type 等信息。
整理原始实验数据，确保每个结果可追溯到具体 SQL 和具体执行计划。
为成员C、成员D提供统一的数据文件和典型计划，不负责深入解释AI模型。
必须产出：
实验环境说明1份、SQL查询清单1份、原始结果表1份、Estimated Rows vs Actual Rows基础图1–2张。
成员C：基数估计误差与困难场景负责人
根据成员B的数据，先分析“正常场景”：单表过滤或简单Join中，PostgreSQL的Estimated Rows与Actual Rows是否接近。
设计“困难场景”：多表Join、数据倾斜，或人为构造具有强相关性的属性，例如 city 与 zipcode，使传统独立性假设更容易失效。
使用 Q-error 对误差进行统一量化，并比较正常场景与困难场景的差异。
解释误差来源，重点围绕统计信息、属性相关性、选择率估计和多表连接中的误差累积，不需要训练神经网络。
如果时间允许，可增加 PostgreSQL Extended Statistics 作为传统修正机制的补充对照。
必须产出：
Q-error统计表1份、正常/困难场景对比图2–3张、至少1个强相关属性典型案例、结论文字。
成员D：执行计划影响与典型案例分析负责人
从成员B、C的实验结果中挑选1–2个最有代表性的失真案例，不追求案例数量，追求解释完整。
分析底层基数估计误差如何向上层传播到Cost估计，并观察是否引起Nested Loop、Hash Join、Merge Join或Join Order等计划变化。
对比Estimated Rows、Actual Rows、Estimated Cost、Actual Time等指标，形成一条完整的因果分析链。
将典型执行计划整理成易读的执行计划树或流程图，避免直接把大段PostgreSQL文本计划原样放进PPT。
如果实际实验中没有发生Join算法切换，也应如实呈现，重点说明基数误差对Cost与中间结果规模的影响，不人为制造结论。
必须产出：
典型案例1–2个、执行计划对比图/树1–2张、影响链路图1张、案例分析文字。
成员E：AI前沿方法深化与实验结果衔接负责人
不再重复上学期对MSCN、DeepDB、NeuroCard、PRICE等方法的基础介绍，而是围绕实验暴露出的具体问题进行归类。
回答“哪一类AI方法针对哪一种传统估计缺陷”：例如Query-driven方法如何直接学习查询到基数的映射，Data-driven方法如何学习联合分布，可迁移方法如何缓解跨库泛化与部署成本。
更新近年的学习型基数估计和AI查询优化发展趋势，形成结构化比较，而不是简单堆叠论文摘要。
重点讨论AI方法仍面临的泛化、训练数据成本、工作负载漂移、推理开销、稳定性和数据库内核集成难点。
负责把实验结论重新接回小组课题：实验不是为了证明“传统方法完全失效”，而是说明为什么学习型方法具有研究价值。
必须产出：
AI方法比较表1份、“实验问题—对应AI方法”映射图1张、前沿趋势总结1份、最终结论素材。
四、四个技术成员之间的协作关系
四位技术成员不应完全并行、互不联系，而应按照以下依赖关系推进：
成员B：实验数据采集  →  成员C：误差分析  →  成员D：计划影响分析  →  成员E：AI方法解释与前沿衔接
成员A（PPT负责人）贯穿全程，从四人处收集阶段成果并统一成最终PPT。这样可以避免出现“实验是一块、AI调研又是一块，两部分互相没有关系”的问题。

七、建议的对外表述
本学期在上学期“SQL 与 AI 协同优化”前沿技术调研基础上，进一步聚焦传统查询优化器的基数估计问题。小组通过 PostgreSQL 与 TPC-H 进行轻量化实证分析，对比正常查询、复杂多表连接及属性相关场景中的估计值与实际值，进一步分析基数估计误差对代价估计和执行计划选择的影响，并结合 MSCN、DeepDB、NeuroCard、PRICE 等学习型方法，讨论 AI 查询优化技术针对传统优化器局限所提出的解决思路及其工程落地挑战。
