# 数据字段说明

所有 CSV 均为 UTF-8 BOM，便于 Excel 直接打开；JSON 为 UTF-8。根目录 results 下的相对 `plan_file` 可直接定位原始计划。

## 原始查询与节点表

| 字段 | 含义 |
| --- | --- |
| phase | baseline 基线、reanalyze_control 只刷新统计、extended 增加扩展统计 |
| query_id / title / group / source | SQL 编号、中文名称、场景和数据来源 |
| repeat / is_warmup | 0 为预热；1 至 3 为正式测量 |
| plan_rows / actual_rows | 根节点每次执行估计与实际行数，本轮根节点 loops 均为 1 |
| actual_loops | 节点循环次数 |
| q_error | 正基数 max(E/A, A/E)；实际零行为空，不当作 0 |
| q_error_safe | 将 E 与 A 分别下限截为 1 后计算，仅用于零行诊断 |
| zero_actual | 标记实际输出为零的节点或查询 |
| total_cost | PostgreSQL 内部代价单位，非毫秒 |
| actual_total_time_ms | 根节点每循环 Actual Total Time |
| execution_time_ms | 查询级 Execution Time，包含 EXPLAIN 分析执行开销 |
| planning_time_ms | 查询级 Planning Time |
| sql_sha256 | 不含末尾分号的 SQL 的 UTF-8 SHA-256 |
| plan_file | 对应原始 JSON，包含完整子树、buffer、过滤与连接条件 |
| node_path / parent_path | 以 0 开始的树路径，例如 0.1.0 |
| plan_rows_per_loop / actual_rows_per_loop | 子节点按每循环的基数，PostgreSQL 可能四舍五入 Actual Rows |
| actual_rows_total_approx | Actual Rows × Actual Loops，是近似总工作量，不用于单次 Q-error |
| executed | loops 大于 0；未执行节点不计算误差 |

`query_runs.csv` 共 144 条，`node_runs.csv` 共 364 条，均保留预热记录。原始 JSON 中还保留 Startup Cost、Shared Hit/Read Blocks、Rows Removed by Filter 等未全部扁平化的字段。

## 汇总

`query_summary.csv` 共 36 条查询配置组合。三次正式执行的根节点基数完全一致；保留一份基数及其误差，对三种时间分别计算 median、min、max。`representative_plan` 指向一个正式执行计划，不意味着该次耗时恰为中位数。

`qerror_statistics.csv` 按 phase 和 group 聚合，每个查询仅计一次，排除实际零行的查询，显式输出 n_queries、n_positive、n_zero。p50、p90、p99 使用 NumPy 线性插值；每组仅 1 至 5 条查询，高分位只作描述，不作生产尾部分布推断。

`stats_*.json` 保存三个阶段的单列 pg_stats；`extended_statistics.json` 保存实际多列统计对象类型、依赖和联合 distinct 信息。`table_counts.csv` 为精确 COUNT(*)，`table_estimates.json` 为监控统计估计值，两者意义不同。

`data_provenance.json` 为 DuckDB 数据生成时的版本、字段和 CSV SHA-256；`csv_verification.json` 为 CSV 按类型回读后的行数与散列比对。它们描述生成及导出过程，PostgreSQL 导入行数由 table_counts.csv 另行核对。
