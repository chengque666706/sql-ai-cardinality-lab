# 实验环境说明

采集开始于北京时间 2026 年 10 月 2 日 12:45。本机 Windows 11，Intel Core i9-14900HX（24 核 32 线程），物理内存约 47.8 GiB。PostgreSQL 在 Docker Desktop 的 Linux 容器中运行，未把宿主全部 CPU 用作查询并行度。

## 版本与配置

PostgreSQL 17.6（Debian 17.6-2.pgdg13+1），Python 3.12.14，DuckDB 1.5.6，Matplotlib 3.11.2。镜像固定为 `postgres:17.6`，摘要 `sha256:00bc86618629af00d2937fdc5a5d63db3ff8450acf52f0636ec813c7f4902929`。

| 设置 | 值 | 目的 |
| --- | --- | --- |
| shared_buffers | 256 MB | 固定共享缓冲区 |
| work_mem | 64 MB | 固定排序和哈希内存上限的基础值 |
| max_parallel_workers_per_gather | 0 | 避免并行节点行数口径混淆 |
| jit | off | 减少编译开销干扰 |
| default_statistics_target | 100 | TPC-H 单列统计目标 |
| 合成相关列统计目标 | 1000 | 样本容量覆盖本实验 30 万行表 |
| random_page_cost / seq_page_cost | 4 / 1 | 保留默认磁盘代价比 |
| autovacuum | off | 专用静态实验库采集期间防止自动统计刷新 |
| statement_timeout | 180 秒 | 单条查询上限，本次未发生超时 |

`results/environment.json` 记录原始设置值；shared_buffers 与 effective_cache_size 使用 8 KiB 块单位，work_mem 使用 KiB，不能把裸值直接读成 MB。采集连接显式执行的 SET 命令也保存在该文件。

## 数据与建模

通过 DuckDB 官方 core tpch 扩展 `CALL dbgen(sf=1)` 生成八表。导出 UTF-8、无表头、竖线分隔 CSV，双引号用于引用和转义，NULL 为 `\N`。DuckDB 仅生成与校验数据；所有执行计划、估计基数和实际基数均来自 PostgreSQL。

`sql/00_tpch_schema.sql` 保存原始字段类型，`sql/01_constraints.sql` 保存实际主外键和索引。TPC-H 八表在 `tpch` schema，合成表在 `synthetic` schema。导入后 `VACUUM (ANALYZE)`，采集期间不修改数据。

合成数据来自固定整数生成规则，不使用随机数据种子。corr_independent、corr_dependent、corr_skewed 各 300000 行；cross_customers 为 10000 行、cross_orders 为 300000 行。单列统计容量覆盖全表，本次三个阶段 pg_stats 快照逐字节相同，核验见 `数据核验.md`。

## 采集与时间口径

采集每次通过新的 `psql` 连接执行相同 SET 命令和 `EXPLAIN (ANALYZE, BUFFERS, SETTINGS, VERBOSE, FORMAT JSON)`。每个查询每配置预热 1 次，正式执行 3 次，每轮查询顺序以 20261002 加轮次为随机种子。阶段固定顺序：baseline、reanalyze_control、extended。

基数统计使用三次一致的行数值；时间使用三次中位数，并保留最小、最大和原始值。每个阶段仅一次统计构建，三次执行不是三次独立建库或统计采样。没有清理操作系统页缓存，预热不意味着所有数据都在 256 MB 共享缓冲区内。

全部时间以毫秒计，但 `Total Cost` 使用优化器内部代价单位。节点 `Actual Total Time` 为每循环的包含子节点的时间，不能跨节点简单相加。查询 `Execution Time` 是服务端分析执行时间，不是客户端往返时延。

## 复现与生命周期

参照仓库 README。容器无外部网络且不发布端口，仅通过 docker exec 访问专用实验库。数据库约 1.77 GB；数据卷保留，可后续继续实验。停止使用时运行 `docker stop sql-ai-cardinality-lab-pg`，再次运行用 `docker start`。

`run_experiment.py --init` 遇到已存在的实验 schema 会拒绝执行；`--collect` 遇到已有 query_runs.csv 会拒绝覆盖。独立运行 02_synthetic.sql 会重建本实验 schema，仅应在本专用数据库中执行。新一轮需要先备份旧结果，避免混合两个实验的证据。
